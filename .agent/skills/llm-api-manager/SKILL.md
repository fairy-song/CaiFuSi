# LLM API 集成审查与开发规范

在编写、修改或审查与大模型 (LLM) API 请求、响应解析或提示词构建相关的代码时，必须严格遵守以下规范：

## 核心规则

1. **API 密钥安全 (零容忍)**
   - **必须**检查 API 密钥是否从环境变量中读取（例如 `.env` 文件或系统环境变量）。
   - **严禁**在代码中硬编码任何 API 密钥或敏感凭证。如果发现硬编码，必须立即重构为环境变量读取。

2. **完善的错误处理**
   - **必须**检查 API 请求是否包含完善的错误处理逻辑。
   - 错误处理必须包括但不限于：
     - 超时控制与重试机制 (Timeout & Retry)
     - 频率限制处理 (Rate Limit / HTTP 429)
     - 网络异常处理、服务不可用 (HTTP 5xx) 处理

3. **响应数据结构化验证 (强制)**
   - **强制要求** AI 的响应数据在传递给前端或下游业务逻辑之前，必须经过严格的结构化校验。
   - 验证要求：
     - 如果预期是 JSON 格式，必须验证其是否为有效的 JSON，并且字段和类型是否完全符合预期的 Schema。
     - 绝不能直接盲目信任并传递 LLM 的非结构化或未经验证的输出。
     - 遇到解析失败或格式错误时，必须进行安全降级（Fallback）或向上抛出明确的异常。

当你的任务涉及 LLM API 调用时，请自动应用上述规则对代码进行审查、编写和修复。
