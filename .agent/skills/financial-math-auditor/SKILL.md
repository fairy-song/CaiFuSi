# 财务与高精度计算代码审查规范

在编写、修改或审查涉及金额、汇率、收益率、账户余额等一切金融或精密数值的计算逻辑时，必须严格遵守以下规范，以彻底杜绝浮点数精度丢失问题。

## 核心规则

1. **严禁用原生运算符计算金额**
   - **绝对禁止**在财务相关数据的计算中直接使用语言原生的加减乘除运算符（如 `+`, `-`, `*`, `/`）。
   - 由于 IEEE 754 浮点数标准的限制，原生浮点运算（如 `0.1 + 0.2`）会产生精度损失，这在金融场景是不可接受的。

2. **强制使用高精度数学库**
   - 所有涉及金额或高精度数值的运算，**必须**使用专门的高精度数学库。
   - **推荐库（根据语言选择）：**
     - **前端/Node.js (JavaScript/TypeScript):** 强制使用 `decimal.js`、`bignumber.js` 或 `big.js`。
     - **Java/Kotlin:** 强制使用 `java.math.BigDecimal`。不可使用 `double` 或 `float` 进行财务计算，且初始化 `BigDecimal` 时应优先使用 `String` 构造函数而非 `double`，或使用 `BigDecimal.valueOf()`。
     - **Python:** 强制使用 `decimal` 标准库（`from decimal import Decimal`）。
     - **Go:** 强制使用 `math/big` 或提供类似功能的第三方高精度库（如 `github.com/shopspring/decimal`）。
     - 其他语言：必须采用该语言标准中被认可的高精度或任意精度数字类型。

3. **数据存储与传输：最小单位整型化**
   - **确保**所有金额或货币数据在**数据库层**及 **API 传输层**（Request/Response JSON 载荷等），均以**最小货币单位**（如人民币的分、美元的美分）的**整型 (Integer)** 进行表达、存储和传递。
   - 只有在终端 UI 展示给用户时，才将这些整数除以相应的倍数（如 100）并格式化显示（如转换为元）。对于复杂币种或多币种场景，必须明确金额对应的单位与币种代码。

当你的任务涉及金融数据处理或数值金额计算时，请开启此审查模式并自动应用上述规则。
